# FactoryForge 路线图：从 3D 布局编辑器到通用数字孪生工具

目标：一个**跨行业通用**的 3D 数字孪生工具。造船厂是第一个演示与落地场景，后续扩展到离散制造、仓储物流、化工能源等行业。
**3D 资产管理**作为核心能力贯穿各阶段。

## 设计原则

1. **行业无关的内核 + 行业资产包**：编辑器、数据模型、渲染、资产管理不包含任何行业知识；行业相关的模型、模板、演示场景以"资产包"形式提供（`common`、`shipyard`，后续 `warehouse`、`chemical` 等）。
2. **场景是数据，渲染只是视图**：孪生文档（实体、属性、关系）独立于 three.js 场景。
3. **资产与场景解耦**：场景只引用资产 ID；资产有元数据、版本和缩略图，可替换、可复用、可打包。
4. **离线可部署**：工厂多在内网，不依赖任何外部 CDN 或云服务。
5. **只读接入 OT**：3D 端不直接控制现场设备。

## 现状问题与对应阶段

| 问题 | 现状 | 解决阶段 |
|---|---|---|
| 依赖外网 CDN | three.js 从 jsdelivr 加载 | 1 |
| 无类型、无构建、无 CI | 纯 JS | 1 |
| 行业内容写死在一个文件里 | `assets.js` 混合了通用和船厂素材 | 1（资产包） |
| 自定义模型不能保存 | .glb 只存在内存 | 1（浏览器端资产库）→ 2（服务端） |
| 渲染性能 | 造船厂约 1,200 个绘制对象，每帧重绘 | 1（静态合并、按需渲染）→ 4（实例化、LOD） |
| 物体没有业务属性、层级扁平 | 只有名称/类型/位置/颜色和"分组" | 2 |
| 撤销用整份快照 | 场景大时变慢 | 2（命令模式） |
| 动画是假的 | 正弦函数驱动 | 3（数据驱动） |

## 阶段 1：工程化（本次进行中）

- TypeScript + Vite，three.js 用 npm 固定版本（0.160.0），去掉 CDN，构建产物可直接离线部署
- 资产包架构：`AssetPack { id, name, industry, categories, assets, scenes }`，资产 ID 带命名空间（`shipyard/drydock`），旧布局文件的旧 ID 自动映射
- **3D 资产管理 v1**（浏览器端，IndexedDB 持久化）
  - 导入 GLB/GLTF：设置单位、向上轴、原点（底部中心 / 中心 / 保留）、分类、标签、行业
  - 自动生成缩略图，统计三角面数、材质数、尺寸、文件大小
  - 资产管理器：按包/分类/标签/行业筛选和搜索，编辑元数据，替换新版本（场景中的引用自动更新），查看引用次数，删除，导出原文件
  - 缺失资产用占位框显示，保留数据不丢失
  - 项目包（`.ffproj.json`）：布局 + 用到的自定义模型一起导出导入
- 性能：每类素材的静态部件按材质合并（缓存复用），场景无变化时不重绘，状态栏显示绘制调用数
- 质量：单元测试（Vitest）、端到端测试（Playwright）、GitHub Actions CI，合并到 main 后自动部署 GitHub Pages

## 阶段 2：数据模型与后端

- 孪生文档：实体树 `厂区 → 区域 → 产线/工位 → 设备 → 部件`，参考 ISA-95 层级
- **设备模板**（参考工业 4.0 资产管理壳 AAS）：属性定义、数据点、状态枚举（运行/停机/故障/维修）、绑定的 3D 资产；实体是模板实例。模板随行业资产包提供
- 业务属性：设备编码、型号、额定参数、外部系统 ID（MES/EAM/ERP）
- 撤销/重做改为命令模式
- 后端：项目/场景/资产存储（PostgreSQL + 对象存储），场景版本与差异对比
- **资产管理 v2**：服务端资产库、版本历史、多项目共享、权限，与浏览器端 API 保持一致
- 坐标：统一米制，支持导入厂区 CAD 总图作为底图对齐

## 阶段 3：实时数据（第一个真实落地场景）

```
PLC / 传感器 ──OPC UA / Modbus──> 采集网关 ──MQTT──> 消息服务器
                                                    ├─> 时序数据库（历史）
                                                    └─> 后端 ──WebSocket──> 前端 3D
```

- 数据绑定：数据点 → 实体属性 → 视觉效果（位置、颜色、闪烁、3D 标签）。资产声明可驱动的部件（现有的 `parts` 动画部件即为雏形），模板声明数据点，绑定配置连接两者
- 插值平滑、数据过期标记"离线"、高频降采样
- 历史回放时间轴
- **船厂试点**：船坞区龙门吊状态监控（小车位置、起升高度、载荷、状态告警）→ 跑通后再推广
- 原型可用 Node-RED 接入，正式版使用专用采集服务

## 阶段 4：资产管线与大场景

- 服务端模型转换：STEP / IFC / FBX / OBJ → glTF，Draco/Meshopt 几何压缩、KTX2 纹理，自动生成 LOD
- 资产校验：面数/纹理尺寸预算、命名规范、比例检查
- 重复物体实例化（InstancedMesh / BatchedMesh）、视锥剔除、three-mesh-bvh 加速拾取、后处理描边
- 厂区级大场景使用 3D Tiles 流式加载

## 阶段 5：可视化与应用

- 编辑器与**运行时查看器**分离（大屏 / 日常使用只需查看器）
- 告警列表与 3D 联动、KPI 看板叠加、图层（区域/类型/状态）
- 测量、剖切、第一人称漫游、视角书签、巡检路线

## 阶段 6：平台与增值

- 权限（查看/编辑/管理员）、操作审计、Docker 私有化部署、OT/IT 隔离
- 仿真分析：船厂吊装作业包络与碰撞、分段运输路径、船坞排期；产线 AGV 路径、离散事件产能仿真、布局方案对比
- 多人协同编辑（Yjs 等）

## 新行业接入方式

新增一个行业 = 新增一个资产包目录，不改内核：

```
src/packs/<industry>/
  index.ts      导出 AssetPack（分类、资产、场景）
  assets.ts     程序化模型或 GLB 资产清单
  scenes.ts     演示场景
```

阶段 2 起资产包还会包含设备模板；阶段 4 起可以在资产管理器中直接导入整包（GLB + 元数据）。
